# Word 原生批注契约

准备写批注时读取，并配合 `word-edit-output.md` 执行彩色修改及台账验收。优先使用环境已有 documents 工具与其当前文档操作说明；不要将本文件中的机制描述当作已经执行成功的工具调用。

## 定位与写入

- 保留源文件的散列摘要，使用不同输出路径。保留所有已有批注、回复、修订、书签、公式、字段、超链接、页眉页脚、图表和样式，不接受或拒绝修订来简化审校。
- 读取时保存文档部件和段落/表格单元格位置，再记录字符起止位置及精确原文。相同文字出现多次时必须依靠位置和上下文消歧，不全局替换或默认第一处命中。偏移以同一提取方式计算，不预先清理空白或标点。
- 有修订时，以可确认的当前可见文本理解句子；无法把可见文字可靠映射回 XML 时，仅暂停相关位置的写入并说明，不能静默改变修订状态。
- 一条批注对应一个明确错误。最小范围是能够指认错误的最短实际文字，不设固定字符上限；一般只需一个词或短语。未落实的缺词问题选紧邻的实有短语；已落实的补词锚定新增文字。写入批注前按修改后文本重新定位，不用已失效的原始偏移。
- 需要跨 run 时在精确字符边界拆分文本 run，复制原 run 属性，保留 `xml:space`、制表符和换行等节点。不能用纯文本重新生成整个段落。字段、公式、超链接、修订等复杂结构不允许破坏性拆分；工具无法可靠处理则换支持精确定位的工具，仍不能处理时记录未完成位置，不扩大为整段批注。
- 正文常规 OOXML 批注包含唯一 `w:id` 的 `commentRangeStart`、`commentRangeEnd`、`commentReference` 及 `word/comments.xml` 中对应的 `w:comment`；维护 comments relationship 与 content type。新增 ID 不与已有 ID 冲突，已有评论及现代评论相关部件保持不变。其他文档部件需核对其支持情况与关系，不能机械套用正文路径。

## 最终核验

1. 源文件 SHA-256 与开始时一致；输出可解压且 XML 可解析。
2. 每条新批注 ID 都有正确配对的开始、结束和引用，关系目标有效。按锚点重新提取文字，必须与问题清单精确相等；批注数与实际写入问题数一致，没有空批注或无锚批注。
3. 对照源文件检查正文文字、表格、图表、公式、字段及修订；正文及颜色变化必须逐项匹配修改台账，其他内容保留；仅批注模式除添加批注和保留格式的 run 拆分外不改变内容。检查原有批注及附属部件仍在，未涉及的包部件保持原样。
4. 渲染最终 Word 并逐页查看，核对布局无新增错位或缺字。渲染输出通常不能可靠显示批注，必须另做第 2 项结构检查；若有 Word UI 能力，检查批注侧栏和点击定位。未做 UI 检查就明确记录“Word 批注侧栏未验证”，不以 XML 检查替代此结论。
5. 校验失败先修复副本并复核。无工具完成必要写入或验证时说明具体未完成项，不把问题清单、仿批注的正文文字或 PDF 当作已完成的批注 Word。
